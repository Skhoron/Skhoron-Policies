## Как сообщить об уязвимости

**Не создавайте публичный issue для нераскрытой уязвимости.**

Контакт по умолчанию: **Skhoron@proton.me**
Если для этого проекта указан другой контакт — используйте его; см. также `CODE_OF_CONDUCT_CONTACT.md`.
[При необходимости замените контакт на специфичный для проекта.]

Если для репозитория включён GitHub Security Advisories, можно использовать его приватный механизм сообщения об уязвимостях.

В сообщении желательно указать:

- версию или commit, где найдена проблема;
- шаги для воспроизведения;
- минимальный PoC, если он безопасен для предоставления;
- потенциальное влияние на конфиденциальность, целостность или доступность;
- известные способы обхода или временные меры, если они есть.

Не отправляйте реальные пароли, токены, приватные ключи или другие секреты.

## Что ожидать

Целевые сроки проекта:

- подтверждение получения — до 7 календарных дней;
- первичная оценка — до 30 календарных дней;
- дальнейшие сроки зависят от сложности и серьёзности проблемы.

Сроки являются целевыми, а не гарантированными.

После исправления проект может опубликовать security advisory и указать исследователя с его согласия.

## Scope

Перед публикацией заполните этот раздел конкретными компонентами проекта и версиями.

Примеры категорий, которые могут быть релевантны:

- удалённое выполнение кода;
- обход авторизации или политики доступа;
- утечка данных или секретов;
- sandbox escape;
- path traversal;
- SSRF;
- небезопасная обработка входных данных;
- denial of service.

## Что не является security report

Обычные ошибки, feature requests и вопросы использования проекта следует отправлять через обычные каналы проекта, если они не создают угрозу безопасности.

## Disclosure

Не публикуйте детали уязвимости до того, как проект и исследователь согласуют безопасный способ раскрытия, если преждевременная публикация может увеличить риск для пользователей.
